# Spatial World Foundation

This document defines the metric and procedural spatial model for the current main island.

## Canonical world

`src/data/mainWorldAreas.ts` is the lifecycle registry. Only the ten `MAIN_WORLD_AREA_IDS` are active macro regions. Every other entry in `AREAS_DATABASE` is legacy/archive data; old redirect aliases remain available only for save and migration compatibility.

`src/data/poiTerritories.ts` remains the authored source of truth for current macro-region shape. The spatial backend does not invent replacement macro regions.

## Physical scale

The current island is calibrated to **120 km² of land**. The source map is 1672 × 941. The backend measures the combined normalized area of the ten authored polygons, preserves the raster aspect ratio, and derives a metric envelope of approximately **17.81 km × 10.02 km**. The surrounding rectangle includes ocean/non-land; the canonical land polygons occupy about **67.23%** of it.

Region area, centroid, bounds and area share are therefore derived from geometry rather than hand-authored balance constants.

## One persistent world seed per run

The existing `buildingSimulation.worldSeed` is the root **world DNA** for spatial generation. It is persisted in save data and regenerated by `resetGame()` for a new run.

- same seed + same generator version recreates the same world;
- a new run receives a new seed;
- construction/build-grid generation and spatial-world generation share one root seed;
- generated terrain need not be stored as hundreds of save objects while seed and generation version remain stable.

`src/simulation/spatial/worldGeneration.ts` composes the generated world from that root seed.

## Spatial hierarchy

```text
Main Island
  -> Macro Region (10 authored polygons, stable between runs)
    -> Habitat Patch (seeded geometry + terrain)
      -> Drainage / watercourse topology
      -> Per-seed Local Site Pool
        -> Local Site instances (seeded position and properties)
          -> Gameplay / ecology / resource semantics
      -> Future trails / crossings / encounter spaces
```

The macro map remains recognizable between campaigns while the playable local wilderness underneath it can differ substantially.

## Procedural habitat and terrain

`src/simulation/spatial/habitatPatches.ts` uses a nominal 600 m lattice whose global origin is shifted by world seed before clipping against the fixed macro polygons. Each seed therefore changes local patch boundaries, centroids and patch IDs while conserving the same 120 km² island.

Terrain is generated as spatially correlated deterministic fields. Each patch carries elevation, slope, roughness, wetness, drainage, canopy/cover/forage/aquatic suitability, movement impedance, habitat tags and terrain tags.

## Generated hydrology

`src/simulation/spatial/terrainHydrology.ts` derives drainage from generated elevation. Patches drain into lower adjacent patches when possible; upstream catchment area accumulates downhill and combines with wetness/aquatic suitability to classify seasonal streams, streams, rivers and wetland channels.

This is an abstract patch-scale drainage topology, not yet a rendered river spline.

## Procedural local-site catalog and per-seed pools

`src/simulation/spatial/localSiteCatalog.ts` defines **70 natural local-site archetypes** plus three required macro landmarks. The natural catalog spans water/hydrology, terrain/geology, vegetation/resources, wildlife-use, coastal and disturbance families.

`src/simulation/spatial/localSiteGeneration.ts` first scores every archetype against the generated terrain/hydrology. Unsupported archetypes are excluded. Supported ones then compete inside deterministic category quotas using terrain support, rarity and seed-specific affinity.

The result is a `GeneratedLocalSitePool`: one seed may emphasize marshes, wallows and flood debris; another may emphasize karst shafts, talus, bat roosts and mineral licks. A campaign does not need to contain every possible local-site type.

Individual instances still require local patch suitability. Rare and exceptional archetypes have stricter local thresholds.

Old concepts such as `Medicinal Glade`, `Kapok Grove`, `Wildlife Nest`, `Clay Pit` and `Jungle Trail` survive only as local-site archetypes. Their legacy area IDs never re-enter macro geometry.

Plane Wreck, Limestone Cavern and Ruin Complex remain guaranteed exactly once per world, with exact local placement selected from generated terrain inside their stable macro regions.

## Local-site functional semantics

`src/simulation/spatial/localSiteProfiles.ts` gives **all 73 local-site types** an explicit machine-readable function.

Each profile defines:

1. **player activities** — gather water, forage food/medicine, gather material/fuel, fish, hunt, trap, salvage, shelter, camp, cross, climb, survey or explore cave;
2. **gameplay effects** — movement impedance, navigation value, shelter quality, camp suitability, hazard and visibility;
3. **ecology effects** — forage, cover, water, breeding habitat, prey refuge, predator opportunity, aquatic nursery value, decomposition, disturbance sensitivity and affinity for broad fauna guilds;
4. **resource opportunities** — resource family, relative abundance, renewability, seasonality, extraction impact and optional mappings to existing item IDs.

Resource families are broader than the current inventory catalog. Fresh water, fish, insects, eggs/feathers, honey, tubers and similar ecological resources can exist before every resource has a dedicated item. Existing material families such as clay, stone, bamboo, resin, timber, driftwood and shells already map to current items where appropriate.

Examples:

- **Burrow Colony**: high breeding habitat and prey refuge, almost no harvest value;
- **Animal Trail**: lower travel impedance, strong wildlife corridor and predator/hunting opportunity, no direct resource yield;
- **Freshwater Seep**: dependable water, wildlife concentration, sensitive to overuse;
- **Fallen Giant**: finite deadwood plus strong decomposition/invertebrate/refuge value;
- **Rock Shelter**: primarily shelter/camp value;
- **Fruit Grove**: seasonal food concentration that attracts both prey and predators;
- **Predator Den**: territorial/breeding habitat and danger rather than a loot node;
- **Plane Wreck**: finite salvage and navigation landmark, not renewable ecology.

`aggregateLocalSiteInfluenceByPatch()` converts spawned sites into normalized patch signals. `GeneratedSpatialWorld.localSiteInfluenceByPatchId` exposes site-derived forage, cover, water, breeding habitat, prey refuge, predator opportunity, aquatic nursery value, decomposition, disturbance sensitivity, shelter/camp quality, hazard/navigation and resource richness.

These signals are intentionally **read-only foundation data for now**. Current fauna, predator, hydrology and resource balance do not consume them yet. This avoids accidental rebalance while later ecology, gathering, travel and camp systems gain one shared source of truth.

## Travel foundation

`src/simulation/spatial/spatialTravel.ts` builds a lightweight adjacency graph from generated habitat patches and exposes a read-only Dijkstra route estimator. Existing `distanceKm` and `baseTravelMinutes` remain live gameplay data until generated trails, slope barriers, river crossings, weather/load/fatigue effects and route validation are added.

## Ecology integration plan

Fauna and predator populations should later migrate from macro-region buckets toward patch-aware populations. The spatial layer is intended to support local density, habitat-specific carrying capacity, home-range overlap, spatial predator competition, terrain/site refugia, breeding/nesting/wallow/feeding-site effects, water-linked movement, extraction-driven degradation and local extirpation/recolonization.

No fauna/predator balance values are changed by this foundation PR.

## Reproducibility contract

Procedural generation must obey:

1. **same seed + same generation version = same spatial world and same local-site pool**;
2. **different seed = materially different local terrain/site topology and vocabulary while preserving the macro map**;
3. **a natural local site may spawn only if its archetype is enabled for that world and its patch satisfies local requirements**.

The spatial smoke test verifies those rules plus complete local-site profile coverage, valid item references, normalized effects, exact 120 km² area conservation, polygon containment, drainage direction and cross-region route connectivity.
